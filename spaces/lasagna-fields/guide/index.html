Who it is for, and how to use it

  
A lasagna field is the input that the lasagna surface fit in villa reads. With it ready, nobody has to spend GPU time predicting it again.

  

    
Researchers
Read it like any OME-Zarr
Open the arrays with zarr, tensorstore or any OME-Zarr viewer. Coordinates are the scan's own voxels, divided by 2 for cos and by 4 for the other channels. The format table below says exactly what is stored.

    
Teams building tools
Point lasagna at the manifest
SCAN.lasagna.json is the manifest that the lasagna tools read, with relative paths to the four channels. Of the ten fields above, every scan but PHerc0841 has a center line in vesuvius-center-lines.

    
Everyone else, rivals included
Same head start for all
These fields are public so that nobody has to spend a GPU day before trying an idea on these scrolls. Use them, compare against them, and tell us if you find a problem.

  

  
From download to first numbers

  

    
Install the Hugging Face client and zarr.
pip install -U "huggingface_hub[cli]" "zarr<3" numpy

    
Stream it (above), or download a scan or just a region, and check it. sha256sum -c SHA256SUMS checks every file; add --ignore-missing after a partial download.

    
Unpack the parts, then the fix tar last. The fix tar (the meta tar, for a Lasagnetta field) holds the joined manifest, so it must overwrite the per-part ones.

    
Load and decode. Normals are stored as uint8 as v × 127 + 128; nz is not stored, so take sqrt(1 - nx² - ny²). Each card's load_example.py runs as is.

  






  
How it was made

  
Every step ran on Hugging Face Jobs from scripts, with each part's record kept. Nothing was edited by hand.

  

    
Same settings as the published fields
The lasagna code in villa at commit db3dbea2, lasagna-preprocess predict3d --tile-size 192 with default chunks and levels, and the scrollprize/lasagna model model_current.pt at revision de45f011. On a test crop of PHerc0343 these settings reproduce the published lasagna field to within 2 of 255 at every voxel compared. Bigger tiles and torch.compile ran faster in testing but changed the output, so they were not used.

    
Split into parts that never share a chunk
Each scan was cut into boxes whose edges sit on multiples of 1,024 scan voxels, each small enough to finish in one Job. Because of that alignment, every chunk of every pyramid level is written by exactly one part, so the parts join without blending. PHerc0175A, the first scan, used an earlier layout whose coarsest level was rebuilt across tile edges; its card gives the details.

    
Predict on GPUs
One Job per part on an NVIDIA RTX PRO 6000, at the scan's native resolution with no resampling:  parts in all.

    
Join and check
The parts were joined into one store, with a check that no chunk appears twice. A seam check then compares the step across each part edge with the steps beside it (1.0 means no step; the limit is 1.5). Finally the card's own load snippet was run on two real parts before upload.

    
One flag, checked properly
PHerc0841 flagged one edge: cos at z 1,024 stepped 1.62 times its neighbors. A single run straight across that edge gave the same field as the joined parts, byte for byte, in all 1,084 level-1 cos chunks and all 760 level-2 chunks of the four channels there. So that step is in the scan itself, not a seam.

    
Seven more scrolls, 29 October 2026
PHercMANBp and PHerc0343P got villa fields the same way from their 2.4 and 2.2 µm scans read at level 2, one 1,024-slice slab per part, with no step at any part edge (worst seam ratios 1.203 and 1.101). PHerc0009B, PHerc0172, PHerc0500P2, PHercMAN5 and PHercMANB got Lasagnetta 0.1.1 fields: three students averaged, cos blur 0.5, cos offset 0.04, part edges on multiples of 512 scan voxels, values kept only where the masked scan holds CT. Each card gives that scan's agreement with villa's net and what the release's self-check said there.

    
Publish with checksums, and unpacked for streaming
Each dataset carries SHA256SUMS, an index.json with every part's box and hash, the previews and the tested load example. The same parts were then unpacked into the public bucket, with the joined manifest written last, so tools can read chunks by URL.

  






  
Format

  
The same layout as the lasagna fields in the open data. Replace SCAN with the scan's name.

  

    
FileRead atScaleStored as

    
      
SCAN_cos.ome.zarrLevel 1Every 2nd scan voxeluint8; peaks on papyrus sheets and dips between them

      
SCAN_grad_mag.ome.zarrLevel 2Every 4th scan voxeluint8 gradient magnitude, encoded as the manifest says (grad_mag_encode_scale)

      
SCAN_nx.ome.zarr, SCAN_ny.ome.zarrLevel 2Every 4th scan voxeluint8 surface normal components, v × 127 + 128; nz not stored

      
SCAN.lasagna.jsonThe manifest: groups, their zarr paths and scale-downs, base_shape_zyx and the boxes computed

      
Every arrayzarr v2, chunks 64 × 64 × 64, Blosc zstd level 3, fill value 0, axes z, y, x, each with coarser levels down to 4

    
  

  
Lasagnetta fields keep the same layout and channels. A field read at level 2 or 3 of a fine scan has its levels counted from that level, as its manifest's base_shape_zyx says.

  
Limits. This is raw model output, and nobody has checked it by eye. Regions the masked scan leaves empty are absent (read as 0). The scan's ends include the mount, and the model produces values there too.
