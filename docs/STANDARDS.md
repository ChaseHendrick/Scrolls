# Standards and measurements

Written 13 October 2026, at the owner's request for one page that lists the standards this repository measures against and sets each one beside the community's practice. It covers only public work: tools in `kit/`, benchmarks on public labeled data, and compute and speed reports. Some evaluation work is kept private, as [`../AGENTS.md`](../AGENTS.md#public-and-private-work) says, and is not described here.

How a standard changes. A standard on this page changes only by a dated owner decision (recorded in [`../AGENTS.md`](../AGENTS.md#standing-user-decisions) and in the change log below) or by a committed, frozen rule: a preregistration under `docs/prereg/`, a run specification under [`compute/modal-specs/`](compute/modal-specs/README.md), or a constant in a `kit/` module with its tests. When this page and such a rule disagree, the frozen rule or preregistration wins, and this page is corrected.

How to read it. Our standards cite the file that defines them, as a relative link. Community items give a URL, the date it was read (13 October 2026 for every community item on this page unless a row says otherwise) and a claim label from [`NOVELTY.md`](NOVELTY.md): **Sourced fact** (an organizer page, an official repository or a paper), **Community report** (someone else's repository or model card), **Interpretation** (our reading). An item marked "not verified on 13 October 2026" could not be read from the session that wrote this page and should be checked before anyone relies on it. Where no community standard exists, the page says so. Nothing here is a reading of any scroll: an ink map is model output ([`../AGENTS.md`](../AGENTS.md#hard-rules-short-form), rule 2).

## 1. Rules every measurement follows

| Rule | Our standard | Defined in |
| --- | --- | --- |
| Controls that can fail | Every check needs a control that a wrong result would fail. Device agreement counts only if a deliberately wrong map is caught (`kit verify --control`). An ink AUC is reported beside the same reader's reverse-depth map on the same pixels. A Dice check against a published map is reported beside the same map displaced. A check whose control was not run is reported as uncontrolled, not as a pass. | [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 4; [`../kit/verify.py`](../kit/verify.py); [`AI-AGENTS.md`](AI-AGENTS.md#evidence-discipline) |
| Preregistration | Readout rules are fixed before any target map exists, with `python -m kit run init --readout ...` or a committed file in `docs/prereg/`. A good readout names the threshold source, a minimum size, the forward against reverse comparison and the expected row structure. A selection rule for a model comparison is written in the run specification before training. | [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 3; [`WORKFLOW.md`](WORKFLOW.md#1-plan); [`plans/2026-10-07-training.md`](plans/2026-10-07-training.md#labelled-controls) |
| Held-out data is read once | Training exclusions, variants, the selection rule and the audit are frozen before fitting. Choices may use one PHerc0841 sheet; an untouched, different sheet audits the selected model once, and the audit result is kept even when it fails. Geometry, thresholds and label registration are never tuned against audit labels. | [`plans/2026-10-07-training.md`](plans/2026-10-07-training.md#labelled-controls) |
| Count every attempt | Every variant tried is counted and reported, including the ones that were not promoted. | [`plans/2026-10-07-training.md`](plans/2026-10-07-training.md#labelled-controls); example: 33 variants in [`logs/2026-10-08-d9v2-finetune-sweep.md`](logs/2026-10-08-d9v2-finetune-sweep.md#depth-windows-of-the-best-checkpoint) |
| One run against run-to-run variance | A number from one run says so ("one run per setting"). Sampling noise in an AUC is measured with a block bootstrap, not assumed. A speed ratio comes from repeated, alternating runs and medians (section 4). A difference smaller than the measured noise is not called a difference. | [`../kit/auc.py`](../kit/auc.py) docstring; [`logs/2026-10-12-b300-gpu-stages.md`](logs/2026-10-12-b300-gpu-stages.md#measured-so-far); [`logs/2026-10-07-production-speed.md`](logs/2026-10-07-production-speed.md#repeated-real-data-measurements) |
| Claim labels | Sourced fact, Organizer result, Community report, Model output, Null, Candidate (private), Untested idea; AGENTS.md rule 5 adds Interpretation, and some logs add Measured for our own runs. Three words are kept apart: ink detected (a model's map), letters visible (a person sees letterforms), legible (papyrologists read them). Only the last wins prizes. | [`NOVELTY.md`](NOVELTY.md); [`QUALITY.md`](QUALITY.md#docs); [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 5 |
| Provenance | A run record states who ran what, when, on which machine and from which inputs, with one SHA-256 digest over the record (`kit provenance write` and `check --files`, schema 1). `kit run record` stores a command line with the SHA-256 of its files. Each row of [`results.json`](results.json) carries its reader, settings, device, window, edge, who measured it and its source. | [`../kit/provenance.py`](../kit/provenance.py); [`../kit/ledger.py`](../kit/ledger.py); [`results.json`](results.json) |
| Units | Distances in voxels, with the voxel size stated (PHerc0139 w045 9.362 µm, PHerc0841 9.366 µm) and µm where it matters. Areas in cm². AUC to four decimals in [`results.json`](results.json). Costs in USD with their source (list price and date read, or billed amount). Dates as YYYY-MM-DD. Local run times in UTC. | [`results.json`](results.json) `segments`; [`compute.md`](compute.md#local-runs-time-and-electricity); [`compute/modal-pricing.md`](compute/modal-pricing.md#1-modal-rates) |
| Data and outward steps | No scroll data, maps or weights in Git. Nothing is posted, submitted, rented or opened upstream without the owner's go-ahead. | [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rules 6 and 8 |
| Code | `kit/` changes need tests. Passing tests checks the snapshot, the templates, the thresholds and the ledger rules; it does not show that a GPU pipeline runs or that a scroll holds ink. | [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 7; [`TESTING.md`](TESTING.md#what-the-tests-pin); [`QUALITY.md`](QUALITY.md#kit) |

## 2. Ink detection

### What we measure

| Measure | Our standard | Defined in |
| --- | --- | --- |
| Primary score | Pixel AUC (the chance a labeled ink pixel scores above a labeled non-ink pixel) against the organizers' 2026-09-18 human labels, inside the segment's supervision mask only. Labels are read at pyramid level 2 and mapped onto the map by nearest neighbor; a scale that differs between the axes by more than 0.005 is refused. Pixels where the map is exactly 0 are left out unless `--keep-zero`, and their count is reported. Command: `python -m kit auc`. | [`../kit/auc.py`](../kit/auc.py); [`results.json`](results.json) `about` |
| Depth controls | The reverse-depth map, scored on the same pixels, is the required control. The depth-shuffled volume (`kit shuffle`, default seed 20261007, or `kit layers --shuffle SEED`; after aviad12g) is the second control. Forward, reverse and shuffled scores are reported separately; forward minus reverse is not a corrected accuracy. | [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 4; [`../kit/layers.py`](../kit/layers.py); [`plans/2026-10-07-training.md`](plans/2026-10-07-training.md#labelled-controls) |
| Window | Each segment has one 640 px window of densest labeled ink, scored with a 64 px edge left out (`--crop Y0 Y1 X0 X1 --surface-shape H W --inner 64`). Without the edge, a bare-crop map and the same window of a whole-segment map differed by up to 0.03 AUC; with it they agree to four decimals on all three segments tested. | [`results.json`](results.json) `segments`; [`../README.md`](../README.md#novel-findings) finding 2 |
| Uncertainty | `--bootstrap N` resamples square blocks of 107 px (1 mm at 9.366 µm) and gives a 95 % interval; the help text calls 300 draws plenty; the seed defaults to 0. `--compare MAP` scores a second map on the same pixels with the same draws and gives the paired difference, its interval and the share of draws in which the first map is not ahead. On PHerc0841 the published team maps have 95 % half-widths of 0.008 (w00) to 0.038 (ag405), so a ranking by a smaller margin on one segment is noise. | [`../kit/auc.py`](../kit/auc.py); [`../kit/cli.py`](../kit/cli.py); [`../README.md`](../README.md#novel-findings) finding 8 |
| Ranking released readers (Gate A) | `python -m kit gate`: mean forward AUC over PHerc0841's three crops (w00, ag896, ag405) with `--inner 64`; forward minus reverse at least 0.10 on every crop; one reader beats another only by at least 0.02 mean AUC. A Mac `ink_9um` seed 42 score must equal the committed CPU bar to four decimals (one unit of slack for rounding), or the run is reported as differing in crop, labels or code. | [`../kit/gate.py`](../kit/gate.py) (constants `MIN_LEAD`, `MIN_GAP`, `INNER`) |
| Promoting a fine-tune | In the public fine-tune sweep the bar was fixed in the run specification before training: a mean of at least 0.8820 over the w00 and ag896 crops, which is the better of d9v2 (0.8612) and Reader v2 (0.8620) plus 0.02, with reverse well below forward. 33 variants were scored and none was promoted. | [`logs/2026-10-08-d9v2-finetune-sweep.md`](logs/2026-10-08-d9v2-finetune-sweep.md#setup) |
| Letter-scale score | `python -m kit hpscore`: Pearson correlation of map and labels after removing a 48 µm Gaussian blur from both (port of the ShribyrLabs `hp_score.py`), against a null of the key rolled by 150, 300 and -300 px at 9.362 µm. Our key is the human labels, so our values are on a different scale from the ShribyrLabs report's and compare only with each other, at the same blur. No pass bar. | [`../kit/hpscore.py`](../kit/hpscore.py) |
| Device agreement | `python -m kit verify REF CAND --control BAD`: at most 2 of 255 gray levels apart on all but at most 0.01 % of pixels, and the control must be caught. Verdicts: `pass`, `pass-uncontrolled`, `fail`, `control-not-caught`. The tolerance leaves margin above villa PR #1865's report (at most 1 of 255 on 0.002 % of pixels). | [`../kit/verify.py`](../kit/verify.py); [`mac.md`](mac.md#runbook-verify-mps-against-cpu-on-the-control-segment) |
| Triage order | `python -m kit rowscore` (port of Bullo27's text-row periodicity score) gives an order in which to look, not a verdict. | [`../kit/rowscore.py`](../kit/rowscore.py); [`rowscore.md`](rowscore.md) |
| Ensembles | `python -m kit ensemble` averages maps of one surface; it never averages weights across seeds. | [`../kit/ensemble.py`](../kit/ensemble.py) |
| Known-truth calibration | `python -m kit phantom` makes synthetic carbon-ink phantoms with known truth, to stress a detector and calibrate AUC noise. | [`phantom-and-viewer.md`](phantom-and-viewer.md#kit-phantom-synthetic-carbon-ink-with-known-truth) |

What pixel AUC does not measure. It measures ranking, not legibility ([`plans/2026-10-07-training.md`](plans/2026-10-07-training.md#labelled-controls)). A blurred map can score well, which is why the letter-scale score exists. TAUIL reports that shifting the labels by 60 µm moves a human-label AUC of this kind by at most 0.005 for Reader v2 and `ink_9um` on PHerc0841, so it cannot detect a label registration error (Community report, [TAUIL-Abd-Elilah/pherc0826-first-letters-search](https://github.com/TAUIL-Abd-Elilah/pherc0826-first-letters-search)).

### The community's standards for ink

| Who | Standard | Source and label |
| --- | --- | --- |
| Kaggle Ink Detection, 2023 | A machine-learning competition in which "hundreds of teams tried building the best machine learning model for detecting ink in open fragments" (Sourced fact, [scrollprize.org/grandprize](https://scrollprize.org/grandprize)). Its metric, its public and private split and the winning scores are not verified on 13 October 2026: the Kaggle pages render by script and could not be read from the session that wrote this page. | [competition](https://www.kaggle.com/competitions/vesuvius-challenge-ink-detection); not verified on 13 October 2026 |
| Official trainer and tutorial | Balanced accuracy (mean of ink and non-ink recall) on held-out validation-mask regions, reported during training. In the trainer's code the confusion counts use a 0.5 threshold on the sigmoid output, and a best checkpoint is kept only when a `best_checkpoint_metric` is configured. | [scrollprize.org/tutorial5](https://scrollprize.org/tutorial5); villa [`ink_detection/training/metrics.py`](https://github.com/ScrollPrize/villa/blob/4eecd08fd91d1afa2beedc0d2edc3b09d2d79bda/vesuvius/src/vesuvius/ink_detection/training/metrics.py) and [`train.py`](https://github.com/ScrollPrize/villa/blob/4eecd08fd91d1afa2beedc0d2edc3b09d2d79bda/vesuvius/src/vesuvius/ink_detection/training/train.py) at commit `4eecd08` (read 13 October 2026); Sourced fact |
| Organizers, 2026 | Validation Dice on pseudo-labels ("a provisional label created from model output and human review"); predictions on a held-out segment shown as figures; the words AUC, benchmark and leaderboard do not appear on the page. | [scrollprize.org/2026_open_problems](https://scrollprize.org/2026_open_problems); Sourced fact |
| PHerc. 1667 paper | Readings accepted on three written criteria: the sampled surface "geometrically tight to the papyrus layer in the CT volume", letterforms "consistent across repeated renderings or inference passes", and the transcription "independently endorsed or resolved by consensus". Ink models are "used as visibility amplifiers for expert inspection, not as autonomous reading systems". No numeric ink metric in the main text. | [arXiv:2606.29085](https://arxiv.org/abs/2606.29085) (June 2026); Sourced fact |
| EduceLab fragment study | Eight-fold cross-validation over fragment halves; pixel metrics including F0.5 (chosen because it "weights precision higher than recall"); then character-level recall and false-positive rate against a papyrologist's transcription made from the images alone. | [arXiv:2304.02084](https://arxiv.org/abs/2304.02084); Sourced fact |
| TAUIL-Abd-Elilah | Human-label pixel AUC on eight fixed held-out segments with the 2026-09-18 labels, all three PHerc0841 segments among them (six scrolls, as our 7 October reading of the README recorded); the mean over the eight and the PHerc0841 mean reported side by side. | [pherc0826-first-letters-search](https://github.com/TAUIL-Abd-Elilah/pherc0826-first-letters-search); [`logs/2026-10-07-community-scan.md`](logs/2026-10-07-community-scan.md); Community report |
| Reader v2 (Domenico Russo) | Pixel AUC against human labels and against a team map on held-out segments ("same data, same masks, same metric for every model"), and a false-alarm rate on blank papyrus at 80 % ink recall; one training seed, no interval. | [huggingface.co/domenicor046/reader-v2](https://huggingface.co/domenicor046/reader-v2); Community report |
| Bullo27, v8in-12gb | AUC and average precision inside the team's supervision mask within the labels' bounding box, reverse depth as control, a letter-scale correlation (48 µm high-pass) and a stroke-shape measure (elongation); three fine-tune pass criteria written before the first fine-tune ran. | [Bullo27/v8in-12gb](https://github.com/Bullo27/v8in-12gb); Community report |
| ibarapascal, ink-disagree | On PHerc0841, score the annotated part (validation intersected with supervision), or report both; block bootstrap with 2,000 resamples. | [ibarapascal/ink-disagree](https://github.com/ibarapascal/ink-disagree); Community report |
| ShribyrLabs report 02 | 48 µm high-pass correlation against the team's 2.4 µm prediction, with a rolled-key null (0.004); on that scale noise about 0.01, blobs 0.04, a case where a person made out four letters 0.076, the highest-scoring 9 µm maps 0.11 to 0.14; run-to-run noise 0.005 is the bar for a difference. The report's own correction notes that the four-letter case sits on a scroll in the base model's training data, so 0.076 may be optimistic. The page does not name its author; `kit hpscore` credits Chris Scheirer's `hp_score.py`. | [ShribyrLabs/vesuvius-reports](https://github.com/ShribyrLabs/vesuvius-reports/tree/main/02-9um-ink-reader-benchmark); Community report |
| khj1222, vesuvius-challenge | Held-out splits by whole annotated region, three-fold cross-validation to set a noise floor (improvements below about 0.03 F1 called noise), and an audit of leakage through official validation masks. | [khj1222/vesuvius-challenge](https://github.com/khj1222/vesuvius-challenge); Community report |

No shared, organizer-run benchmark exists for 9 µm scroll ink, and none of the organizer pages read for this page uses AUC. The de facto community comparison is per-segment pixel AUC against the 2026-09-18 human labels on PHerc0841's three segments with reverse depth as a control, but each group defines the scored pixels differently (Interpretation, from the sources above). No standard binarization threshold exists either: the trainer's validation metric cuts at 0.5 (villa code above, Sourced fact), bnleft's readout takes the median predicted probability over a control segment's labeled ink (Community report, [readout.md](https://github.com/bnleft/first-light-pherc0211/blob/main/prereg/readout.md)), and a published PHerc0826 null used 0.7843, the median `ink_9um` value on a training segment's labeled ink ([`../README.md`](../README.md#novel-findings) finding 3).

## 3. Surface tracing and surface prediction

This repository has no written public standard for tracing: no committed benchmark, reference set, trace length, repeat count or pass bar. What exists is below; the gaps are in section 8.

| Measure | Our practice | Defined in |
| --- | --- | --- |
| Surface prediction against a published map | Dice of our prediction against the published one on the same box, with a displaced control: the maps from three cards reached Dice 0.9998, and moving the map 4 voxels in x dropped it to 0.036. One run per setting. No acceptance threshold is set. | [`logs/2026-10-12-b300-gpu-stages.md`](logs/2026-10-12-b300-gpu-stages.md#measured-so-far) |
| Do two segments trace the same sheet | `python -m kit overlap`: mesh gaps and label agreement, against displaced matches. On PHerc0841, w00 and ag896 sit a median 8.6 voxels apart and their labels agree (Dice 0.83, against at most 0.69 for 200 displaced matches). | [`../kit/overlap.py`](../kit/overlap.py); [`../README.md`](../README.md#novel-findings) finding 5 |
| Do two traces' ink maps agree | `python -m kit collate`, against a control and displaced matches. | [`../kit/overlap.py`](../kit/overlap.py) |
| Published meshes and cross-scan transforms | `python -m kit meshaudit`, under a written protocol; changes after the first run are added as dated sections, and those added after seeing results are marked exploratory. | [`plans/2026-10-07-mesh-hypothesis.md`](plans/2026-10-07-mesh-hypothesis.md) |
| Surface corrections | `python -m kit surfacefix` is experimental; its acceptance checks are listed with it. | [`surfacefix.md`](surfacefix.md#acceptance-checks) |
| Comparing a trace with published windings | Practice, not yet a written standard: each vertex is assigned to the nearest published winding within a distance cut-off, and the report gives the dominant winding and its share within 4 voxels, the area, switch edges and transverse self-crossings. This compares a trace with published windings; it does not prove sheet identity on its own. So far one seed on one scroll, single runs. | [`logs/2026-10-12-upstream-reports.md`](logs/2026-10-12-upstream-reports.md); [`../README.md`](../README.md#novel-findings) finding 13 |

## 4. Speed, compute and cost

| Measure | Our standard | Defined in |
| --- | --- | --- |
| Estimate first, then place the job | Before any job, estimate its time. A job that needs a GPU, or more than about an hour of CPU, runs on Modal from a written run specification (goal, inputs, code, machine with expected time, cost and stopping cap, outputs, checks with a control, a prompt for the runner). Claude cloud sessions can run Modal with `modal[api-proxy-support]`, Chase's sign-in and an allow rule. | [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 11; [`compute/modal-specs/README.md`](compute/modal-specs/README.md) |
| Default machine | `gpu=["B300", "B200", "H200", "H100"]`; for CPU work `cpu=(16, 16)` with threads set to 16, unless a measurement shows the job scales differently. Speed before saving money, inside the approved budget; never past it without asking with an estimate. A frozen specification keeps the machine it was approved with. | [`compute/modal-pricing.md`](compute/modal-pricing.md#default-gpu-and-cpu-for-new-jobs) |
| Prices | Modal list prices with the date read; a fallback list is priced at its dearest entry, the B300 at 7.10 USD/h per GPU (read 2026-10-12). | [`compute/modal-pricing.md`](compute/modal-pricing.md#1-modal-rates) |
| Ledgers | Modal runs: one row each in [`compute/modal-ledger.csv`](compute/modal-ledger.csv) (time, purpose, GPU type and count, GPU and CPU seconds, estimated and actual USD, cumulative USD, notes). Local runs: `python -m kit run local SLUG -- COMMAND` records start and end, wall and CPU time, the device's assumed average watts, kWh and USD at a locally configured rate. `python -m kit compute DIR` gives machine time per run from provenance records. | [`compute/modal-pricing.md`](compute/modal-pricing.md#8-run-ledger); [`compute.md`](compute.md#local-runs-time-and-electricity); [`../AGENTS.md`](../AGENTS.md#hard-rules-short-form) rule 9 |
| CPU speed claims | One warmup per version, then five or six alternating before and after pairs; each timed run in a fresh Python process on one CPU with numerical libraries at one thread and competing compute paused; report medians and the ratio of medians; every output hash must match; state when caches are warm. Examples: a surface correction from 5.2913 s to 2.5508 s (2.0744x); the AUC command with a paired 1,000-draw bootstrap from 372.00 ms to 298.12 ms (1.25x). | [`logs/2026-10-07-production-speed.md`](logs/2026-10-07-production-speed.md#repeated-real-data-measurements); [`logs/2026-10-07-production-scaling.md`](logs/2026-10-07-production-scaling.md) |

### The community's standards for speed and cost

| Who | Standard | Source and label |
| --- | --- | --- |
| villa AGENTS.md | Section 1.4: performance work establishes a baseline, uses a profiler, and reports before and after results with the command line, the dataset, the build type, "iteration counts and summary stats (mean + p50/p95 or min/median/max)". Section 3.1: final numbers from Release builds; no fast-math, reduced precision or relaxed epsilons for a speedup. | [villa AGENTS.md](https://github.com/ScrollPrize/villa/blob/main/AGENTS.md); Sourced fact |
| villa PR template | A "Proof" with "the same input/settings for comparisons", and under Details the exact tested commit, commands, data and checkpoints. | [pull_request_template.md](https://github.com/ScrollPrize/villa/blob/main/.github/pull_request_template.md); Sourced fact |
| villa PR #1865 in practice | One timing per device with chip and torch version (114.1 s CPU against 38.2 s MPS, then 123.1 s against 43.6 s after a rebase); correctness by AUC to eight decimals and map agreement within 1 of 255 on 0.002 % of pixels; merged 8 October 2026. | [villa #1865](https://github.com/ScrollPrize/villa/pull/1865); Community report |
| hyperfine | At least 10 runs by default, optional warm-up runs, and mean, standard deviation, median, minimum and maximum in its exports. | [sharkdp/hyperfine](https://github.com/sharkdp/hyperfine); Sourced fact |
| PyTorch benchmark recipe | Warm up, synchronize CPU and CUDA, benchmark with thread settings "representative of real use cases" (the module runs in one thread by default), and inspect the median and mean of the measurement. | [PyTorch benchmark recipe](https://docs.pytorch.org/tutorials/recipes/recipes/benchmark.html); Sourced fact |
| MLPerf training rules | A fixed number of runs per benchmark (3 or 10 in the current table); drop the fastest and slowest and take the mean of the rest; "running multiple iterations of N runs to try find the lowest one" is prohibited; seeds logged. | [training_rules.adoc](https://github.com/mlcommons/training_policies/blob/master/training_rules.adoc); Sourced fact |
| NeurIPS checklist | Error bars, with what they capture stated, at least for the experiments behind the main claims; the type of compute workers, memory, the compute for each run and whether the project needed more compute, including preliminary or failed experiments. | [neurips.cc PaperChecklist](https://neurips.cc/public/guides/PaperChecklist); Sourced fact |
| bnleft, first-light-pherc0211 | A per-step table of where each step ran and its wall time; a total cost from the Modal billing report (13.53 USD against a 60 USD cap), about 6.5 h GPU and 1.5 h CPU; the warm-cache run labeled as such. | [bnleft/first-light-pherc0211](https://github.com/bnleft/first-light-pherc0211); Community report |
| Bullo27, first-letters-survey | Measured times as ranges (the network fetch with a median), naming the GPU, the thread count for growing and the network link. | [Bullo27/first-letters-survey](https://github.com/Bullo27/first-letters-survey); Community report |

No prize asks for compute, cost or energy figures beyond a Docker image with its system requirements, and no organizer rule covers timing method (Interpretation, from [scrollprize.org/prizes](https://scrollprize.org/prizes) and the villa sources above).

Community practice. ## 6. Prize-facing measures

How our measures relate. Pixel AUC, the letter-scale score and the row score are ink-map measures; none of them is a legibility measure, and no mapping from them to legibility is known (Interpretation). A First Letters claim needs letters visible to a person and legible to papyrologists ([`QUALITY.md`](QUALITY.md#docs)).

Measurements taken without a written standard, or standards that disagree. Each is a known gap, not a finding.

| Gap | Where it shows |

| No public tracing benchmark: no reference set, trace length, repeat count, thread count or pass bar, and no `kit` command scores a trace against published windings | Section 3 |
