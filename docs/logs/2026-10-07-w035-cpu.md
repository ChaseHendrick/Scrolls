# 2026-10-07: w035 CPU reference run, and what the "control" shows

Research notes, not claims. Labels per [`../NOVELTY.md`](../NOVELTY.md).

## Run (Sourced fact: commands and files below)

- villa `main` at `e0bbb8b`, `python -m vesuvius.ink_detection.inference.infer`, `--overlap 0.5 --blend-mode hann --batch-size 1 --no-compile --direction both`.
- Input: the published 9.362 µm surface volume of PHerc0139 segment w035 (`python -m kit fetch w035`, 2,223 objects, 1.02 GB, shape 28 × 5,820 × 5,240). The model reads layers 6 to 22 (17 of 28), 6,458 patches per direction.
- Checkpoint: `scrollprize/ink_9um` `hybrid_3d2d-seed42/step-075000.pth`, SHA-256 `e635558ae6a1a807a7e5ec1e83adfd45bc3c0ac53883ea43f1d4e085d62a9cab` (seed43: `2aeaa85a35ef28d7bc7bf3e848c4a6a91385e9132710927fdba41133c4ecb28f`).
- Machine: Linux container, 4 CPU cores, 16 GB, Python 3.14, torch 2.14.1 (CPU). Forward direction took about 26 minutes while villa's test suite shared the CPU.
- Output: forward map 5,820 × 5,240 uint8; median 66, 99th percentile 200, max 222.

## Observation (Model output)

The forward map shows clean Greek letterforms in the upper left (ρ ΝΟ, ΝΛ, Τ, Ρ, Ν, ΥϹΙ) and blotchy speckle everywhere else.

Compared with the segment's published labels (`ink-labels/2.399um-volume-20260102150214/20260918`, level 2, 5,660 × 5,100, which is about the 9.36 µm grid): every clean letterform lies inside a supervised label region and matches the painted label stroke. Two labels painted outside the supervised regions (an Ο and a Τ below the last row) do not appear in the map.

Reading: on this training segment the model reproduces its training labels where it was supervised. The clean letters are memorization, not evidence that the model finds ink it was not trained on. The prize rules forbid overlap between training and prediction regions for exactly this reason ([prizes](../prizes.md)).

What this changes:

- w035 remains a valid **pipeline** check (if it shows no letters, something is broken) and a valid input for a CPU vs MPS comparison, which needs only the same input on both devices.
- It is not a **generalization** check. Use a held-out labelled segment for that. Bullo27 reports clear rows on held-out PHerc0139 w045 (Community report, [first-letters-survey](https://github.com/Bullo27/first-letters-survey)); not checked here.
- Docs that called w035 proof that the pipeline "works" were corrected the same day (README, start-here, compute, mac, `kit plan`).

Comparison image: generated locally under `work/` (gitignored, model output on the Challenge's CC BY-NC data).
