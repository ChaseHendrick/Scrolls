# PHerc0841 may not be held out from Hecate (2026-10-09)

**Question.** Since 7 October this repository has called PHerc0841 a scroll "in no candidate's training set" (AGENTS glossary, `docs/AI-AGENTS.md` rule 6, `docs/results.json` `held_out`) and "the labelled scroll no released reader trained on" (`docs/tricks.md`). Is that right for every reader the repository cites?

**Answer.** For `ink_9um`, v8in, v8in-1447, d9v2 and Reader v2, yes, as far as their published training lists show. For Hecate it is not established. Hecate starts from the organisers' canonical 2 µm model, and that model's committed trainer lists all three labelled PHerc0841 segments as training fragments. The team's published `new_canon_autoresearch_recipe` maps of PHerc0841 come from the same recipe, so they are probably in-sample too. No number changes; the wording around the numbers does. Labels follow [`../NOVELTY.md`](../NOVELTY.md).

## What stays unverified

- Which fragment list the run behind the released `ink_canonical_2um` actually used. The code and the checkpoint name, epoch and step count match, but the training run itself is not public.
- Hecate's own training split. Its manifest is not in the model repository, and how its stages used PHerc0841 data is not established here. Hecate's own stages may have held PHerc0841 out; that would not undo exposure through its starting weights.
- Which checkpoint rendered the team's published PHerc0841 maps.
- Indirect exposure of the other readers. d9v2 and Reader v2 train on dense targets from the team's predictions on other scrolls (TAUIL README line 72; Reader v2 README lines 127-132). If those predictions come from a model trained on PHerc0841 labels, some of that knowledge could reach them without any PHerc0841 data (Untested idea).

## Also corrected today: README finding 1

Two wording fixes to finding 1, which the owner kept with its 8 October correction (owner to review):

- **Like-for-like crop.** The finding set v8in's 0.738 (a map inferred on the bare 640 px w045 crop) against 0.914 for `ink_9um`, which is the same window cut from `ink_9um`'s whole-segment map: the mix finding 2 warns about. The bare-crop `ink_9um` score on that window is 0.9074 (reverse 0.3835). All three rows are in [`../results.json`](../results.json) (Sourced fact; the AUCs are Model output).
