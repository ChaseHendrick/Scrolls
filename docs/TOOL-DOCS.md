# Tool docs: the standard every tool page follows

Chase asked on 16 October 2026 (09:58 UTC) for "all current, past, and future tool docs" to be "extremely detailed and readable by both human and agent". This page says how. Every tool in this repository has one page in [`tools/`](tools/README.md), written to this standard, and `python -m kit.tooldocs check`, which the tests run, fails when a tool has no page or a page breaks the rules below. AGENTS.md hard rule 16 points here.

Two readers use every page. A person reads it top to bottom to learn what the tool is for and whether to trust its output. An agent jumps to one section by its fixed name, copies a command, and needs every option, default, output field and exit code written out exactly. The rules below serve both: the same sections in the same order on every page, plain sentences, and exact text wherever something will be pasted or parsed.

## What counts as a tool

Anything a person or an agent runs or calls:

- each `python -m kit` command and action (one page may cover a family, such as the experiment ledger's `run init`, `run status` and `run check`);
- each `kit/*.py` module and `kit/` package: on its own page when it has its own use, or named in the Code field of the page of the command that uses it;
- each `python -m kit.MODULE` entry point, such as `python -m kit.cloudcost`;
- each script or script folder directly under `scripts/`;
- agent (MCP) tools, apps and Spaces, released weights, the project skill and the installable package;
- past tools: retired ones still in the tree, and tools whose code lives only on another branch or in history.

`python -m kit.tooldocs check` enforces the first four: every kit module and package, every entry directly under `scripts/`, and every kit command and action must be named by some page.

## Where pages live

- **`docs/tools/ID.md`**, one page per tool. The id is lowercase letters, digits and hyphens: the command name where there is one (`auc`, `letterread`), otherwise a short name (`run-ledger`, `mac-scripts`).
- **[`docs/tools/README.md`](tools/README.md)** is the index. Its table, and [`docs/tools/index.json`](tools/index.json) for agents, are generated by `python -m kit.tooldocs index`; never edit them by hand.
- **Guides stay where they are.** A tutorial, a model card or an evidence note that already has a home (for example [`letter-reader.md`](letter-reader.md) or [`strokenet.md`](strokenet.md)) stays there, and the tool page links to it in the Guide field instead of copying it. The tool page is the reference: every option, input, output, exit code and failure, checked against the code. This keeps one home per topic (AGENTS.md hard rule 13).
- **Templates:** [`../templates/tool-doc.md`](../templates/tool-doc.md), and [`../templates/tool-doc-branch.md`](../templates/tool-doc-branch.md) for a tool whose code is on another branch. `python -m kit.tooldocs new ID` copies the right one.

## A page, top to bottom

1. **Title**, one line: `# Name: what it does in a few words`.
2. **Summary**: one sentence, at most 300 characters, the first paragraph after the title. The index shows it.
3. **At a glance**: a two-column table with the header `| Field | Value |` and the fields below, in this order.
4. **Sections**: level-2 headings with exactly the names below, in this order. You may add other `##` sections between them; `###` subsections are free.

### At a glance fields

| Field | What to write | Example |
| --- | --- | --- |
| Id | The file name without `.md`, in code | `` `auc` `` |
| Status | One of the four status words below | Current |
| Kind | One or more kind words below, comma-separated | kit command |
| Run | Every entry point, each in code; a library writes None (library) and its import | `` `python -m kit auc` `` |
| Code | Every file of the tool, each in code, paths from the repository root; a folder ends with `/` | `` `kit/auc.py`, `kit/cli.py` (`cmd_auc`) `` |
| Tests | Test files in code, or None and why | `` `tests/test_auc.py` `` |
| Needs | Python version, packages, outside tools and data, with versions where they matter | Python 3.10+, numpy, tifffile, zarr |
| Runs on | Where it should run and how long it takes, with the source of the number | CPU, about 2 s per segment (measured 2026-10-07) |
| Network | None, or every host it contacts and why | None |
| Writes | Nothing (prints only), or every file and folder it creates or changes | Nothing; with `--slug`, a check in `experiments/SLUG/run.json` |
| Go-ahead | Not needed, or Needed and why (posting, uploading, renting compute: AGENTS.md hard rule 8) | Not needed |
| Released | Where it is public and since when | Public `main` since 2026-10-07 |
| Checked | The date, then the commit the page was checked against | 2026-10-16 against commit `27d0e96` |

Optional fields, placed anywhere in the table: **Guide** (a link to the longer guide), **Replaced by** (required when Status is Retired; write Nothing if nothing replaced it) and **Branch** (required when Status is Branch only: the branch and commit that hold the code). No `|` inside a value.

### Status words

| Status | Meaning |
| --- | --- |
| Current | In the tree and fit to use |
| Experimental | In the tree, works, but its result has not passed its own bar or its interface may change; say which in What it does |
| Retired | Still in the tree but not to be used for new work: superseded, or a measured null. The page stays so old results can be read and rerun |
| Branch only | Not on the default branch: the code lives only on another branch, or only in history. The page says where and why |

### Kind words

`kit command`, `kit module` (a library inside `kit/`), `python module` (a `python -m kit.MODULE` entry point), `script`, `script folder`, `agent tool`, `app` (a Space or a web page), `model` (weights), `package` (an installable package), `skill`, `patch` (a patch to someone else's code, such as villa), `workflow` (a CI workflow or a multi-step routine), `data` (a dataset or a manifest a tool reads).

### Sections, in order

| Section | What it must hold |
| --- | --- |
| `## What it does` | Two to five paragraphs in plain words: the problem, what the tool does about it, what it does not do, and what its output must not be called (an ink map is model output, not a reading). Define every internal name on first use |
| `## When to use it` | The situations it fits, then the cases where it does not, each with the tool to use instead |
| `## Quick start` | The shortest real run in a `bash` block that can be pasted, a short excerpt of what it prints, and how to tell it worked |
| `## Commands and options` | One `###` per command or action: the usage line (from `--help`), then a table of every positional argument and option, `\| Option \| Default \| Meaning \|`, defaults from the code. A library uses the heading `## Python API` instead: each public function's signature, arguments, return value and errors. A page may have both |
| `## Inputs` | Every input: format, shape, dtype, units, coordinate convention, where to get it, size limits |
| `## Outputs` | What it prints, every file it writes, every JSON field (`\| Field \| Type \| Meaning \|`, with units) and every exit code (`\| Code \| Meaning \|`) |
| `## How it works` | The method step by step, the constants that matter (name and value from the code) and sources for any published method it follows |
| `## Checks and controls` | The control that lets the result fail (AGENTS.md hard rule 4), how to run it, what a pass and a fail look like, and the claim label the output carries ([NOVELTY.md](NOVELTY.md)) |
| `## Failure modes` | A table `\| What you see \| Why \| What to do \|`, with the exact error messages from the code |
| `## Cost and time` | Measured times and memory with date, machine and source; where it must run (GPU work and long CPU jobs go to Modal, hard rule 11); the cost if it rents anything. Write Not measured rather than guess |
| `## For agents` | The rules in the next section |
| `## Tests` | The command that runs this tool's tests, what they cover and what they do not |
| `## History` | Dated changes, newest first, with PR or commit links; for a retired tool, why it was retired |
| `## Related` | Links to related tool pages, guides, logs and `results.json` keys, each with a few words on why |

A **Branch only** page has a shorter list, since its code is not in the tree: `## What it does`, `## Where the code is` (branch, commit, paths, PR, and the `git` command that fetches it), `## How to run it`, `## Inputs and outputs`, `## Why it is not on the default branch` (with its source, or Not recorded), `## For agents`, `## History`, `## Related`.

## The For agents section

An agent may read only this section and the At a glance table, so it must say, exactly:

- **The command** for the common case, and its machine-readable form (`--json`, an output file), copied from the code.
- **Side effects**: what it reads, what it writes, what it sends over the network. Whether a rerun is safe (idempotent), and what a rerun overwrites.
- **Go-ahead**: what needs the user's yes first (posting, uploading, submitting, renting compute; hard rules 8 and 11) and what never leaves the machine.
- **Success and failure**: the exit codes and the output fields to check, and what a "pass" that should not be trusted looks like (for example a verdict with no control).
- **Never**: what not to do with the tool or its output, such as calling an ink map a reading, scoring on a segment the model trained on, or running a GPU job on a laptop CPU.

## Writing rules

- **Exact where it is pasted or parsed.** Commands, option names, defaults, file names, JSON fields, exit codes and error messages are copied from the code, in code formatting. Placeholders are CAPITALS (`MAP.tif`), each explained under its block.
- **Plain sentences elsewhere.** Short paragraphs, one idea each. Tables for comparisons and for lists an agent will scan.
- **Numbers carry their source.** A default names its constant; a measured time or score gives its date, machine and source (a log, a `results.json` key, a commit). Never invent a number: write Not measured.
- **Claims carry their label** (Sourced fact, Community report, Model output, Interpretation, Untested idea; [NOVELTY.md](NOVELTY.md)).
- **Each page stands alone.** An agent that reads only one page can run that tool correctly; link to background, but do not make the reader assemble the basics from other pages.
- **Terms.** Define internal names on first use and add new terms to [`../GLOSSARY.md`](../GLOSSARY.md). Use villa and VC3D terms where they exist.
- **Style.** Plain sentences, never U+2014 or U+2013 dashes (hard rule 10), relative links that resolve (the tests check them).
- **Public pages carry nothing private** (hard rule 1): no target-scroll maps, triage or verdicts, and no private tools' internals. A private tool that is mentioned links nowhere and says it is private.

## Keeping pages current

- **Change a tool, change its page** in the same change: options, defaults, outputs and the Checked field. `python -m kit.tooldocs check --page ID` checks one page while you write it.
- **New tool, new page** in the same PR: `python -m kit.tooldocs new ID --kind KIND`, fill in every section, then `python -m kit.tooldocs index`. The check fails on a new kit module, command or script folder without a page, so it cannot be skipped.
- **Retire a tool** by setting Status to Retired and filling Replaced by; keep the page.
- **Delete a tool's code** only after its page says Branch only, with the branch or commit that still holds it.

## What the checker checks

`python -m kit.tooldocs check` (and the unit test `tests/test_tooldocs.py`, which runs it) reports one line per problem and exits 1 when there is any:

- the title, the summary (present, at most 300 characters), the At a glance table (every field, in order, none empty, no unknown field);
- Status and Kind words, a date at the start of Checked, Replaced by on a Retired page and Branch on a Branch only page;
- every path in Code and Tests exists (not checked on Branch only pages);
- every `python -m kit COMMAND [ACTION]` in Run is a real command, and every long option of it, and of each of its actions, appears on the page in code;
- every required section, in order, none empty, and no template guidance left on the page;
- every kit module and package, every entry directly under `scripts/`, and every kit command and action is named by some page;
- `docs/tools/README.md` and `docs/tools/index.json` match the pages.

It cannot check that the prose is true. Reviewers check that: run the Quick start, compare each default with the code, and read the error messages in the code against Failure modes.
