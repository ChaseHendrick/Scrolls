# Release media: heroes, cards, GIFs and clips

Every picture and clip under `docs/assets/` is listed here with its size, bytes, media label and license, and has a sidecar JSON (`NAME.json` beside it, schema `scrolls-media/1`) that records the same label, its sizes and SHA-256, its inputs and the command that made it. `tests/test_repo.py` fails when a file has no row or no sidecar, when a row's or sidecar's bytes or pixel size disagree with the file, when a sidecar breaks the public media rule ([`../media/README.md`](../media/README.md): model output, a prize-eligible scroll, held-out labels, a missing data field, command or commit), when a sidecar records a scratch path, when a hero (`*-hero.webp`) is not exactly 1920 x 640 or is over 300 KB, or when anything is over 1920 px wide or 4 MB. Chase asked on 18 October 2026 for a hero on every released tool, in the quality and dimensions of the root README's, and for images, GIFs and videos of released tools. [`scripts/media/`](../../scripts/media/) makes them ([tool page](../tools/media.md)).

## Media labels

Each picture says what it is, first in its caption and again in its sidecar:

| Label | What it means | Allowed here |
| --- | --- | --- |
| Concept illustration | Generated or procedural art: no source scan, model output, recovered text or experimental result | Yes |
| Synthetic demo | A tool running on made-up data, or a screenshot of an interface that shows only made-up data | Yes |
| Real data render | Pixels made from a public scan, with the scan, voxel size, labels drawn (or `none`), segment and volume when they apply, and the credit "Vesuvius Challenge open data, CC BY-NC 4.0" | Only of a public scan that is not prize-eligible, with no held-out labels (PHerc1447's, PHerc0841 ag405's), licensed CC BY-NC 4.0 ([the public media rule](../media/README.md)). Real-data pictures of prize-eligible scrolls stay in Scrolls-private's `docs/media/` |
| Model output | A model's map or score, never a reading | No, for any scroll: Scrolls-private's `docs/media/` |

No picture here shows letter boxes or a suggested reading, and none shows ink, StrokeNet or reader output for any scroll. `scripts/media/common.py` refuses model output under a `docs/assets/` folder and a Real data render that breaks the public media rule, and removes a written file over 1920 px or 4 MB; `hero.py` builds an illustration or demo for this folder only from files already under `docs/images/` or `docs/assets/`, `encode.py` requires a label for any clip written here, and `capture_web.py` never writes its unlabeled frames here.

## The reference style

The root README and the AutoPipeline reference use a matching pair of concept illustrations generated with OpenAI image generation on 18 October 2026. They depict a carbonized papyrus roll, a continuous selected surface and a computational mesh. Both are opaque WebP images, resized from 2172 x 724 pixel generated originals using Lanczos resampling and saved at quality 83. Their 3:1 aspect ratio keeps the repository introduction visible on small screens. There is no text baked into the artwork; the page headings remain readable, selectable text in either GitHub theme.

Refined editorial 3D scientific illustration with soft ivory light from the upper left and restrained copper rim light. Charcoal `#171A1C`, warm ivory `#EEE7D9` and oxidized copper `#B77A54`; close three-quarter view, warm desaturated contrast, seamless charcoal background and no people. The Scrolls composition follows a layered papyrus roll into an open surface mesh. AutoPipeline follows a single selected sheet from its curled geometry into a flattened grid. Both are conceptual: physical unrolling of fragile carbonized papyrus is not the method used by the Vesuvius Challenge.

The tool heroes of 18 October follow the same direction without an image model. `scripts/media/scenes.py` builds each scene from formulas and a seed: a low camera, one subject on a left-to-right diagonal, papyrus as long fibers in strips with frayed edges, and scroll cross-sections as spirals with a start and an end, never rings. `scene.py` renders it at 3840 x 1280 with the ivory key light, a copper rim and a warm floor sweep, and `hero.py` grades it toward the three colors with the reference's warm glow at the upper left, downsamples it with Lanczos to 1920 x 640 and saves WebP at quality 83. They are procedural renders, plainer than the generated pair. Each hero also has a 1200 x 630 social card (`NAME-card.jpg`) for Hugging Face thumbnails and GitHub's social preview: the title, a line and the media label in Inter on a solid charcoal band over the left half, and the hero's subject on the right. The heroes carry no text, except the Starter hero, which floats real screenshots of Starter's interface showing only its made-up practice pixels, so it is a Synthetic demo. StrokeNet has no hero until the rework Chase asked for.

Keep any replacement free of lettering, fabricated ink, score badges and claims of recovered text. Preserve the media label when reusing an asset. Actual software screenshots and synthetic monitor demonstrations keep their own provenance labels. GIFs play inline on GitHub; the MP4s are for release notes and Spaces, where Chase drags them in (a committed MP4 does not play inline in a GitHub README).
