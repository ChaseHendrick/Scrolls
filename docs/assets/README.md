# Release media: heroes, cards, GIFs and clips

Every picture and clip under `docs/assets/` is listed here with its size, bytes, media label and license; `tests/test_repo.py` fails when a file has no row, when a row's bytes or pixel size disagree with the file, when a hero (`*-hero.webp`) is not exactly 1920 x 640 or is over 300 KB, or when anything is over 4 MB. Chase asked on 18 October 2026 for a hero on every released tool, in the quality and dimensions of the root README's, and for images, GIFs and videos of released tools. [`scripts/media/`](../../scripts/media/) makes them ([tool page](../tools/media.md)).

## Media labels

Each picture says what it is, first in its caption and again in its sidecar JSON (`NAME.json` beside it, schema `scrolls-media/1`, which also records its sizes, SHA-256, inputs and the command that made it):

| Label | What it means | Allowed here |
| --- | --- | --- |
| Concept illustration | Generated or procedural art: no source scan, model output, recovered text or experimental result | Yes |
| Synthetic demo | A tool running on made-up data, or a screenshot of an interface that shows only made-up data | Yes |
| Real data render | Pixels made from a public scan, with the scan, segment, voxel size and "Data: Vesuvius Challenge, CC BY-NC 4.0" | No: public Git holds no scan renders. They are kept in Scrolls-private's `docs/media/` until Chase approves a host |
| Model output | A model's map or score, never a reading | No, for the same reason |

No picture here shows letter boxes or a suggested reading on real data, and none shows ink, StrokeNet or reader output for a Grand Prize or First Letters scroll. `scripts/media/common.py` refuses to write a Real data render or Model output under any `docs/assets/` folder.

## The reference style

The root README and the AutoPipeline reference use a matching pair of concept illustrations generated with OpenAI image generation on 18 October 2026. They depict a carbonized papyrus roll, a continuous selected surface and a computational mesh. Both are opaque WebP images, resized from 2172 x 724 pixel generated originals using Lanczos resampling and saved at quality 83. Their 3:1 aspect ratio keeps the repository introduction visible on small screens. There is no text baked into the artwork; the page headings remain readable, selectable text in either GitHub theme.

Refined editorial 3D scientific illustration with soft ivory light from the upper left and restrained copper rim light. Charcoal `#171A1C`, warm ivory `#EEE7D9` and oxidized copper `#B77A54`; close three-quarter view, warm desaturated contrast, seamless charcoal background and no people. The Scrolls composition follows a layered papyrus roll into an open surface mesh. AutoPipeline follows a single selected sheet from its curled geometry into a flattened grid. Both are conceptual: physical unrolling of fragile carbonized papyrus is not the method used by the Vesuvius Challenge.

The tool heroes of 18 October follow the same direction without an image model: `scripts/media/scenes.py` builds each scene from formulas and a seed, `scene.py` renders it at 3840 x 1280 with the same key and rim lights, and `hero.py` grades it toward the three colors, downsamples it with Lanczos to 1920 x 640 and saves WebP at quality 83. Each hero also has a 1200 x 630 social card (`NAME-card.jpg`) for Hugging Face thumbnails and GitHub's social preview; the card carries the title and the media label in Inter, the hero carries no text. The Starter hero is the exception to "no text": it floats real screenshots of Starter's interface, which show only its made-up practice pixels, so it is a Synthetic demo.

Keep any replacement free of lettering on real data, fabricated ink, score badges and claims of recovered text. Preserve the media label when reusing an asset. GIFs play inline on GitHub; the MP4s are for release notes and Spaces, where Chase drags them in (a committed MP4 does not play inline in a GitHub README).
